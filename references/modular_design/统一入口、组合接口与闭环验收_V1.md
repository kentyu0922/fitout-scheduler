# 统一入口、组合接口与闭环验收 V1

配套文件：00_模块化架构与工序规则_V1.md。状态：待实现的规格，不是已有引擎能力。

## 1. Intake 与 Prompt 输出同一份项目定义

最小选择：行业、DB/DBB、主包邀请/公开、城市、面积、起止目标、场地状态。辅助条件按其是否影响范围和主路径展开。

项目定义增加：实际用途（办公/研发/实验/生产等）、已有阶段成果、项目终点、每采购包制度/市场方式、专项范围状态、现场复用/改造界面、项目日历和外部依赖。客户可以不知道；未知项有默认处理策略，不要求填写整套专业问卷。

| 范围状态 | 客户表达例子 | 处理 |
|---|---|---|
| required 需要 | “要一间录音室”；表格选择需要 | 加载对应模块；追问影响结构的缺口，技术细节可留设计确认门 |
| excluded 不需要 | “不含动捕” | 排除动捕；但检查是否与已选用途／依赖矛盾 |
| unknown 待确认 | 空白、未提及、“可能要” | 不等同不需要；列范围待决，不伪装完整项目。可生成明确范围的基础草案 |
| existing_claimed 既有拟复用 | “大楼已经有机房” | 创建能力/状态核查；在证据齐备前不作为已完成前置 |
| existing_verified 已核验复用 | 有对应能力与状态证据并获项目确认 | 用既有接口替代新建工序，保留接入/测试工作 |
| provided_by_others 他方提供 | “UPS由客户另购” | 保留他方采购/到货/验收接口、负责人和日期依据；不删除安装依赖 |

事实来源另记 provided/default_policy/inferred，客户陈述与独立核实分开。existing_verified 必须有引用证据、范围和确认者；客户仅勾“复用”不能自动升级。表格和Prompt同时出现矛盾时询问；用户明确更正旧输入时采用更正并留变更记录。

行业推荐仅影响表格展示排序，不预勾“需要”。表格未勾选按“待确认”处理，若用户明确选择“除已勾选外均不需要”，才把其余可选项记为排除。其他行业的模块仍可按真实需求选择，不把行业标签当硬性禁止。

未知项分级：影响安全／法定动作或基本路线的冲突必须解决或显示相应动作未释放；其他范围未知可先输出受限范围草案。可进行带披露的规划测算，但不能称其已具备施工／使用条件。

## 2. 加载判定顺序

1. 归一化事实、证据、明确修订和冲突。
2. 选择20套之一；判断实际用途是否超出已定义框架。
3. 核对已完成成果：设计已委任或已完成的，不再排完整采购设计周期，改为成果核验/剩余工作。
4. 实例化核心和行业要求；主包选择四路线之一，辅助包保持独立。
5. 加载明确需要的专项，并沿依赖追踪必要接口；依赖可以新建、复用或他方提供。
6. 应用现场、分期、不停业、设备甲供、日历等条件；该加载的必要改造不能因未勾Add-on而遗漏。
7. 合并共用工序，确定唯一责任归属；保留各专项需求，不合并不同验收成果。
8. 建立并核对设计、采购、工作面、安装、测试、交付连接；输出已加载／未加载／待确认理由。
9. 工序逻辑成立后计算日期；精简或完整仅选择输出文件，不改变工序或必须通过的放行条件。

## 3. Add-on 如何适配四套路线

专项技术工序与其发包责任分开。相同实验室或机房模块在四套中复用技术成果要求，设计委任、专项招采位置和责任方按路线适配。

| 主路线 | 专项需求和设计接入 | 专项采购接入 | 安装与测试 |
|---|---|---|---|
| DB＋邀请 | 投标前明确性能及接口；D&B承包商在授权后完成其承担的专项深化，雇主设计保留部分另记 | 在总包范围内按其采购授权执行；甲方直采则建立独立采购包，不重复总包采购 | 按相同设备/工作面/测试门释放；由设计责任矩阵确定审查人 |
| DB＋公开 | 同DB责任结构，公开发包资料须含足够明确的专项范围及评审要求 | 总包公开采购路径与专项供应链分开；不得把每个总包分包自动变为公开采购 | 同一技术成果和接口；必要公示/采购条件放在相应包 |
| DBB＋邀请 | 业主设计顾问把专项需求转成发包设计/规格；承包商承担约定施工深化和厂家配合 | 可含GC包、独立专业包或甲供；每设备只一个采购责任 | 发包设计不自动替代施工释放；专业安装与总包工作面协调 |
| DBB＋公开 | 同DBB设计结构，GC公开采购要求贯穿发包文件和评审 | 单列专业包适用方式；不能从GC公开推断所有采购都公开 | 同一技术成果和接口；验收责任按合同及适用要求 |

采购制度记录为“正式招标适用路线／已确认的其他企业采购路线／需专门规则的政府采购等路线／未知”。具体适用性有依据后才能实例化详细程序；制度名称和企业内部规定不能豁免适用法律。政府采购等若超出四条已定义程序，保留待定接口并明确需专项规则，不套用企业比选替代。

## 4. 关键模块组合规则

| 组合 | 必须具备的关系 | 禁止的替代 |
|---|---|---|
| 机房＋IT迁移 | 迁移策划可提前；目标环境验收释放预部署；业务窗口及回退条件释放切换 | 全楼硬装完工代替机房验收；机房建设自动等于迁移 |
| 动捕＋声学 | 按房间共用围护/机电；尘作及相应环境就绪后安装精密设备；相机到货单独挂接 | 声学验收代替动捕场景验收；动捕相机到货阻断无关机房基础 |
| 交易＋机房＋强化安防 | 各专项就绪接交易业务启用门；整合接口测试并记录各验收依据 | 三条独立甘特线各自结束，没有汇合业务门 |
| 实验室＋洁净室 | 环境控制与相关系统达到测试状态；环境验证和实验安全/运行放行分别保留 | 只完围护就开始洁净分类；洁净合格等于全部实验安全合格 |
| 设备＋特气/CDA/水/电 | 每台设备登记实际所需接口；齐备后释放对应调试 | 一律把所有介质串行；不需的系统也成为设备前置 |
| 设备＋微振/ESD | 按厂家条件与测试状态定义安装、验证先后；系统界面一致 | 全部先完成最终微振测试才允许设备就位，或反过来一律如此 |
| 生物医药＋质量确认 | 工程调试与质量确认可共享合格证据；质量方按批准策略释放适用阶段 | 工程竣工自动等于生产许可/质量放行 |
| 分期＋任一专项 | 每区域有独立就绪和使用门；共享系统能力/隔离验证先满足依赖区域 | 任意删掉全楼接口就宣布提前入住 |
| 不停业＋改造 | 现状/隔离、临时保障、窗口审批和切换恢复验证进入受影响链 | 只更换日历就表示不停业可施工 |
| 关闭扩展FM | 保留基本资料、必要培训、接管责任和项目终点 | 删除搬迁/Day1；把全部基本运维职责当可选 |

## 5. 交付门的定义

节点必须记录对象、成果、签认责任、证据和状态；项目级名称不能替代这些字段。

- DESIGN_RELEASED[p,z]：相关图纸、规格、接口和必要批准满足对应作业。
- EQUIPMENT_RECEIVED[e]：对应设备到货并满足安装接收要求；不是“所有设备全部到货”。
- CONCEALED_RELEASED[工作面,系统]：对应隐蔽检查/试验通过，释放封闭。
- SYSTEM_ACCEPTED[s,z]：约定测试工况、性能及阻断问题已关闭。
- OCCUPANCY_READY[z]：相关安全、适用法定条件、基础设施、环境和运维条件满足人员使用。
- BUSINESS_READY[b,z]：相关IT/专业系统和业务验证满足业务启用；可与人员入驻有不同日期。
- MOVE_COMPLETE[批次]：该批人员/资产完成转移和核验；不与保修结束混淆。
- PROJECT_TARGET：由用户目标指定为移交、搬迁完成或业务启用，绑定对应节点；其他完成节点仍保留。

任何已纳入范围的实体或验证工作，都应能到达相关交付/业务/合同成果。确属独立移交或交付后的工作可有独立终点，不能仅因“没有接Day1”就机械认定错误；必须说明边界。

## 7. 后续实施的验收标准

本节是验收清单，尚未运行这些验收。

| 编号 | 检查 | 通过条件 |
|---|---|---|
| V01 | 20套基础结构 | 每套都有核心、行业与正确路线；行业差异可解释；没有强制未确认专项 |
| V02 | Add-on 单独加载/排除 | 每个模块在适用主干中能接入；删除无悬空依赖、不删除项目终点 |
| V03 | 依赖满足方式 | 新建/既有复用/他方提供都能满足同一接口；不重复建设 |
| V04 | 关键组合 | 上表组合的共享工序唯一，相关就绪门闭合，不机械全串行 |
| V05 | 日期扰动 | 延迟某设备到货影响对应安装及应受影响终点；不阻断无关基础工序 |
| V06 | 专项验收扰动 | 未通过或延迟的专项验收阻断其业务区域启用；合法隔离区域不被无依据拖住 |
| V07 | 入口一致性 | 同义Prompt和intake得到相同组合、模块、证据状态；冲突不被静默覆盖 |
| V08 | 状态与默认 | 空白不变为否；行业推荐不变事实；复用主张不变已核验 |
| V09 | 采购制度 | 邀请不自动省略适用法定条件，不自动启用议价；设计采购与GC分开 |
| V10 | 既有成果 | 已有设计/合同只排剩余工作与必要核验，不重新完整招采 |
| V11 | 实际交付 | 正式入口输出的关系、日期及原生MPP保存重开一致；本轮不声称完成 |

先做结构和接口的定向验证；正式生成优先选上海案例及代表性的风险组合。无需为每个理论排列都生成MPP；新增关系或故障再扩充覆盖。完整回归安排在合适的发布检查阶段，不作为日常每次对话的默认动作。

## 8. 仍须项目输入的事项

需求/容量/设备技术参数、质量和安全目标、设计批准状态、具体采购制度、外部交付责任、属地适用程序及施工/测试窗口，不能从行业名字推导出事实。规格已给定其处理规则；只有这些项目事实需要补充，不要求用户重新设计全部模块。
